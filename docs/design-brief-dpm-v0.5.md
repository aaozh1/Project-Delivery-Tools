## 📌 หน่วยของระบบ — คน-สัปดาห์

```
1.00 คน-สัปดาห์  = คนหนึ่งคนทำงานเต็มสัปดาห์ให้โครงการหนึ่ง
0.50 คน-สัปดาห์  = ครึ่งสัปดาห์
0.25 คน-สัปดาห์  = หน่วยย่อยที่สุดที่ป้อนได้ (ประมาณ 1 วัน)

การวางแผนระดับงวดงาน: "งวดนี้ต้องใช้ Senior 3 คน-สัปดาห์ · Mid 4 · Junior 5.5"
การจัดสรรจริงรายสัปดาห์: "คุณซี → ID-004 = 0.50 · ID-009 = 0.50"
```

**ทำไมคน-สัปดาห์ไม่ใช่ชั่วโมงหรือวัน**
- ตรงกับจังหวะการทำงานจริงของสตูดิโอออกแบบ — คนไม่ได้กระโดดโครงการรายชั่วโมง
- กรอกเร็ว: หนึ่ง Squad 4–6 คน ใช้เวลาไม่เกิน 3 นาทีต่อสัปดาห์
- ความละเอียดเพียงพอต่อการตัดสินใจ: คำถามคือ *"โครงการนี้กำไร 30% หรือ 5%"* ไม่ใช่ *"30% หรือ 31%"*
- ตัวเลขปัดลงตัวสวย ไม่มีเศษ 0.375 ให้ปวดหัว

> **ห้ามมีการลงเวลารายชั่วโมงหรือรายวันในระบบนี้โดยเด็ดขาด** — เป็นการตัดสินใจเชิงหลักการ ไม่ใช่เรื่องที่จะเพิ่มทีหลัง

## 1. โจทย์ในหนึ่งประโยค

> เครื่องมือที่ทำให้ **หัวหน้าฝ่ายส่งมอบงาน / หัวหน้าแผนก / หัวหน้า Squad** ควบคุม **ขอบเขตงาน · เวลา · ต้นทุนค่าแรง (COL)** ของทุกโครงการ ในหน่วย **คน-สัปดาห์** โดยที่ทีมออกแบบใช้เวลากับระบบเพียงสัปดาห์ละ 5 นาที และเวลานั้นถูกใช้เพื่อพัฒนาตัวเขาเอง

## 2. โครงสร้างองค์กร — Squad

```
บริษัท
 └── แผนก (Department) — AR · ID · House · Graphic
      │   หัวหน้าแผนก (Head of Department)
      │   • ดูแลทุก Squad ในแผนก
      │   • ผู้เดียวที่ย้ายคนข้าม Squad ได้
      │   • รีวิวและอนุมัติแผนงาน
      │
      ├── Squad A — หัวหน้า: Senior คนที่ 1
      │    ├── สมาชิก 3–6 คน (Mid / Junior)
      │    └── รับผิดชอบ 2–4 โครงการ
      │
      └── Squad B — หัวหน้า: Senior คนที่ 2
           ├── สมาชิก 3–6 คน
           └── รับผิดชอบ 2–4 โครงการ
```

### กฎของ Squad (บังคับในระบบ)

| กฎ | เหตุผล | ผลต่อดีไซน์ |
|---|---|---|
| **หัวหน้า Squad จัดสรรได้เฉพาะสมาชิกใน Squad ตัวเอง** | ป้องกันการแย่งคนกันเอง และให้ความรับผิดชอบชัดเจน | S6 กรองข้อมูลเป็น squad-scoped ไม่แสดงคนนอก Squad เลย |
| **การย้ายคนข้าม Squad ทำได้โดยหัวหน้าแผนกเท่านั้น** | เป็นการตัดสินใจระดับแผนก มีผลต่อ 2 Squad พร้อมกัน | ต้องมีกลไก **คำขอกำลังเสริม** ส่งถึง HoD |
| **หนึ่งโครงการสังกัดหนึ่ง Squad** | ความรับผิดชอบต่อ Margin ต้องชัดว่าเป็นของใคร | Project ต้องมีฟิลด์ squad |
| **การย้ายคนต้องมีวันเริ่ม–วันสิ้นสุด** | รู้ว่าใครอยู่ Squad ไหน ณ สัปดาห์ใด เพื่อคำนวณ COL ย้อนหลังถูก | เก็บประวัติการเป็นสมาชิก ไม่ใช่แค่สถานะปัจจุบัน |

### ⚠️ ปัญหาใหม่ที่เกิดจากกฎนี้ และวิธีแก้ในดีไซน์

การห้ามข้าม Squad ทำให้ความรับผิดชอบชัดขึ้นมาก แต่สร้าง 3 ปัญหาที่ต้องออกแบบรองรับ ไม่งั้นจะเจ็บภายใน 3 เดือน:

| ปัญหา | อาการที่จะเกิด | ทางแก้ในดีไซน์ |
|---|---|---|
| **Squad ไม่สมดุล** | Squad B ล้น 120% ขณะ Squad A ว่าง 60% แต่ย้ายคนไม่ได้ | บล็อก **Squad Balance** ในหน้า HoD + หน้า S7 ที่เทียบข้าม Squad ได้ |
| **การพัฒนาคนติดกำแพง** | คุณซีต้องผ่านงาน Site เพื่อขึ้น Senior แต่ Squad ตัวเองไม่มีงาน Site เลย 6 เดือน | ปุ่ม **ส่งเรื่องถึง HoD** จากหน้า Growth Profile และหน้าจัดสรรคน |
| **หัวหน้า Squad กักตุนคน** | ไม่ปล่อยคนที่ว่าง เพราะกลัวไม่ได้คืน | หน้า S7 แสดง **คนที่โหลดต่ำติดต่อกันหลายเดือน** ให้ HoD เห็น |

### 🔐 หลักจริยธรรมของโมดูลพัฒนาคนและภาระงาน (บังคับในดีไซน์)
1. **พนักงานเห็นข้อมูลภาระงานและ Growth Profile ของตัวเองได้เสมอและครบ**
2. **ข้อความอิสระในบันทึกรายสัปดาห์ ห้ามนำไปทำคะแนน** — UI ต้องระบุชัด
3. **ห้ามมีการจัดอันดับระหว่างบุคคล** — เทียบได้เฉพาะกับตัวเองในอดีตและค่าเฉลี่ยแผนก
4. **หน้าจอต้องบอกว่าใครเห็นข้อมูลนี้บ้าง** ณ ตอนที่กำลังเขียน
5. ⭐ **หน้าภาระงาน (S7) ต้องอ่านได้ทั้งสองทาง** — โหลดสูงคือความเสี่ยงต่อคน ไม่ใช่แค่ความเสี่ยงต่อโครงการ ภาษาในหน้าจอต้องสะท้อนเรื่องนี้

## 8. หน้าจอโมดูลพัฒนาคน (P1)

### S13 — บันทึกงานรายสัปดาห์ (มือถือเป็นหลัก · 5 นาที ทุกศุกร์)

โครงสร้าง: แถบแจ้งความเป็นส่วนตัว → การ์ดโครงการที่ระบบเติมให้จากการจัดสรร (ติ๊ก Deliverable ที่ทำ · เลือกลักษณะงาน 4 แบบ · เทียบกับที่จัดสรร) → แท็กทักษะ/โปรแกรม → ช่องข้อความอิสระที่**ไม่บังคับ**และมีข้อความกำกับว่าไม่นำไปคิดคะแนน

**ลักษณะงาน 4 แบบ:** `ตามแผน` (ค่าตั้งต้น) · `แก้ตามลูกค้า` · `แก้งานเดิม` · `นอกขอบเขต`

### S14 — Growth Profile + Exposure Matrix

**Exposure Matrix** คือตารางกริด *ประเภทงาน × ขั้นงาน* แสดง 3 ระดับ (ยังไม่เคย / เคย / ชำนาญ) — ตอบคำถามที่การประเมินผลงานทั่วไปตอบไม่ได้ คือ **"คนนี้ยังไม่เคยทำอะไร"**

**เพิ่มใน v0.5:** เมื่อพบช่องว่างที่ Squad ตัวเองเติมไม่ได้ ต้องมีปุ่ม **[ส่งเรื่องถึงหัวหน้าแผนก]** เพราะการย้ายคนข้าม Squad เป็นอำนาจของ HoD เท่านั้น — ถ้าไม่มีปุ่มนี้ ระบบพัฒนาคนจะติดกำแพง Squad และตายไปเอง

**ข้อกำหนดจริยธรรม:** ห้ามจัดอันดับระหว่างบุคคล · ใช้คำว่า *"ยังไม่เคย"* ไม่ใช่ *"ขาด"* · พนักงานเปิดดูของตัวเองได้เสมอ · ต้องดูดีพอที่เขาจะอยากเปิด

## 9. หลักการออกแบบ

## 15. คำถามที่ยังต้องยืนยัน

1. **Blended Rate ต่อคน-สัปดาห์** — บริษัทมีตัวเลขนี้แล้วหรือต้องคำนวณจากเงินเดือนจริง
2. **มีกี่ Squad ต่อแผนก และแต่ละ Squad มีกี่คน** — กระทบดีไซน์ S6/S7 โดยตรง
3. **Squad มีอายุถาวรหรือตั้งตามโครงการ** — ถ้าตั้งใหม่บ่อย ต้องออกแบบเรื่องประวัติสมาชิกให้ดีกว่านี้

5. **เป้า Margin 30%** ใช่ตัวเลขจริงไหม ต่างกันตามสายงานหรือไม่
6. **บริษัทมีเกณฑ์เลื่อนตำแหน่งเป็นลายลักษณ์อักษรไหม** — ถ้ามี Exposure Matrix ควรอิงเกณฑ์นั้น
7. **ใช้ LINE ในการทำงานจริงจังแค่ไหน** — กระทบระบบแจ้งเตือน
8. **สัญญาระบุ "แก้ได้กี่รอบ" ไว้จริงไหม**

## ภาคผนวก A — สูตรคำนวณ

```
หน่วยหลัก = คน-สัปดาห์ (person-week) · ป้อนทีละ 0.25 · เต็มสัปดาห์ = 1.00

COL (ประมาณการ) = Σ (คน-สัปดาห์ที่วางแผน × blended_rate ต่อสัปดาห์ ตามตำแหน่ง)
COL (จริง)      = Σ (คน-สัปดาห์ที่จัดสรรจริง × cost_rate ต่อสัปดาห์)  ← HoPD เท่านั้น

Software Cost   = ค่า License ต่อปี ÷ คน-สัปดาห์รวมทั้งบริษัทต่อปี × คน-สัปดาห์โครงการนี้
Overhead        = อัตรา Overhead ต่อคน-สัปดาห์ × คน-สัปดาห์โครงการนี้

Margin          = มูลค่าสัญญา − (COL + Software + Outsource + Reimbursable + Overhead)
Margin %        = Margin ÷ มูลค่าสัญญา × 100

ใช้ไป %          = คน-สัปดาห์ที่จัดสรรสะสม ÷ คน-สัปดาห์ที่ตั้งงบ × 100
คืบหน้า %        = Σ(น้ำหนัก Deliverable ที่เสร็จ) ÷ Σ(น้ำหนักทั้งหมด) × 100
Health          = ใช้ไป % − คืบหน้า %     → เกณฑ์ตั้งค่าได้ใน Admin Console

EAC (คน-สัปดาห์ตอนจบ) = คน-สัปดาห์ที่ใช้แล้ว ÷ (คืบหน้า % ÷ 100)
Margin ตอนจบ         = มูลค่าสัญญา − (EAC × blended_rate + ต้นทุนอื่นที่เหลือ)
Slip แยกเจ้าของ       = Σ วันที่นาฬิกาอยู่กับ [ทีมเรา | ลูกค้า | ราชการ | ภายนอก]

★ ภาระงานรายบุคคล (รายเดือน)
  % โหลดของคน       = Σ คน-สัปดาห์ที่จัดสรรในเดือน ÷ จำนวนสัปดาห์ทำงานในเดือน × 100
  จำนวนโครงการ       = นับโครงการที่ไม่ซ้ำกันที่คนนั้นถูกจัดสรรในเดือนนั้น
  ระดับสถานะ        🔴 เกิน 110% · 🟡 100–110% · 🟢 65–100% · 🔵 ต่ำกว่า 65%
  เตือนโครงการเยอะ   เมื่อจำนวนโครงการ > เกณฑ์ของตำแหน่งนั้น (ตั้งค่าได้)
  เตือนโหลดต่ำ       เมื่อ < 65% ติดต่อกันตามจำนวนเดือนที่ตั้งไว้

★ Squad
  % โหลด Squad      = Σ คน-สัปดาห์ที่จัดสรรของสมาชิกทุกคน ÷ Σ ความจุของสมาชิกทุกคน × 100
  ความไม่สมดุล      = % โหลด Squad สูงสุด − % โหลด Squad ต่ำสุด ในเดือนเดียวกัน
                     (เกิน 30 จุด = ควรพิจารณาย้ายงานหรือคน)

การใช้กำลังคนบริษัท % = คน-สัปดาห์ที่จัดสรรเข้าโครงการ ÷ คน-สัปดาห์ทั้งหมดที่มี × 100

— จากบันทึกรายสัปดาห์ —
สัดส่วนลักษณะงาน % = จำนวนบันทึกแต่ละประเภท ÷ บันทึกทั้งหมด × 100
Exposure Score    = จำนวนสัปดาห์ที่เคยทำ [ประเภทงาน × ขั้นงาน] นั้น
                    0 = ยังไม่เคย · 1–4 = เคย · 5+ = ชำนาญ
```
